# TaskManagement API

Тестовое задание на позицию Middle C#/.NET Backend Developer.

## Функциональность

- Создание и получение задач
- Завершение задачи с установкой `CompletedAt`
- Удаление задач
- Валидация названия (обязательное, максимум 200 символов)
- Обработка ошибок `400 Bad Request`, `404 Not Found`, `409 Conflict`
- Оптимистическая конкурентность через PostgreSQL `xmin`
- Асинхронная публикация события `task.completed` после сохранения изменений в БД

## API

| Метод | Endpoint | Описание |
|---|---|---|
| POST | `/tasks` | Создать задачу |
| GET | `/tasks` | Получить все задачи |
| PUT | `/tasks/{id}/complete` | Завершить задачу |
| DELETE | `/tasks/{id}` | Удалить задачу |

Пример создания задачи:

```json
{
  "title": "Test task",
  "priority": "High"
}
```

Приоритеты: `Low`, `Medium`, `High`. По умолчанию используется `Medium`.

## Запуск

Необходимы .NET 9 SDK, PostgreSQL и RabbitMQ.

1. Настроить подключение к PostgreSQL и RabbitMQ в `appsettings.Development.json` или через .NET User Secrets.
2. Применить миграции:

   ```bash
   dotnet ef database update
   ```

3. Запустить приложение:

   ```bash
   dotnet run
   ```

Swagger UI доступен по адресу `/swagger` в среде `Development`.

## RabbitMQ

При завершении задачи после успешного сохранения в PostgreSQL событие помещается во внутреннюю очередь и асинхронно публикуется в RabbitMQ.

- Exchange: `task.events`
- Тип: `topic`
- Routing key: `task.completed`
- Формат: JSON

Пример события:

```json
{
  "taskId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "title": "Test task",
  "completedAt": "2026-05-07T12:00:00Z",
  "priority": "High"
}
```

При ошибке публикации событие записывается в лог, а завершение задачи в БД не откатывается.


## Ограничения и возможные улучшения

В рамках тестового задания были сделаны следующие упрощения:

- **Graceful shutdown:** реализован частично. Активные публикации могут быть прерваны при остановке приложения. Планируемая доработка: ожидание публикаций с таймаутом 3 - 5 секунд.
- **RabbitMQ:** для каждого события создаётся отдельное соединение и канал. Можно переиспользовать соединение и добавить переподключение.
- **Надёжность доставки:** используется in-memory очередь. При аварийном завершении процесса события могут быть потеряны. В production рассмотрел бы Transactional Outbox.
